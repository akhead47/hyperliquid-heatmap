03 · 추적 포지션

지갑코인방향수량진입가청산가레버리지청산가 명목액
데이터 범위 · 계산 방식 · 배포 방법

이 화면은 수집에 성공한 지갑의 현재 포지션 표본입니다. 리더보드는 전체 계정 목록이 아니며 계정 평가액은 포지션 규모와 다릅니다. 미추적 지갑, 다른 거래소, HIP-3 시장 및 별도 주소의 하위 계정은 포함하지 않습니다. 전체 시장 커버리지는 알 수 없습니다.

청산가 명목액 = |szi| × liquidationPx. positionValue는 API 원본 그대로 JSON에 보존합니다. null 청산가, 잘못된 숫자, 0 수량은 제외합니다. 롱/숏은 수량 부호로 구분하고 현재가 반대편의 청산가는 별도 제외 건수로 표시합니다. 교차마진·다른 포지션·담보·가격 변화로 청산가는 달라지며, 이 명목액은 실제 강제 매도·매수량을 확정하지 않습니다. 시간축 히트맵은 이 앱에서 실제로 수집한 스냅샷만 누적합니다. 수집 이전 과거 청산 포지션은 복원할 수 없습니다. 흰 선은 기본적으로 수집 시점의 중간가이며, 5분봉 불러오기를 실행하면 Hyperliquid 종가를 표시합니다. 기록 사이에 수집하지 않은 구간은 비어 있습니다.

주소별 clearinghouseState 순차 호출, 429/5xx 지수 백오프, 요청 시간 제한을 적용합니다. 실패한 지갑의 과거 포지션은 섞지 않습니다. 갱신은 탭이 열려 있는 동안만 실행되며 스냅샷은 이 브라우저에 저장됩니다. 누적 기록은 코인·시점 조합 최대 240개로, 초과 시 오래된 기록부터 삭제합니다. 장기 보관은 누적 기록 저장을 이용하세요. 이전 버전에서 넓은 가격 구간으로 저장된 기록은 정밀하게 복원할 수 없습니다. 이번 버전부터 BTC는 $250 원본 구간을 저장합니다. 저장된 구간을 다른 구간 수로 표시할 때 겹치는 가격 폭에 비례해 재분배하므로 화면 집계는 근사치입니다. 자동 갱신마다 표본 지갑 성공률이 달라지면 강도도 달라질 수 있습니다.

HTML 단독 배포: 이 파일을 index.html로 GitHub 저장소 루트에 올린 뒤 Settings → Pages에서 해당 브랜치 /root를 선택하세요. 서버·설치·API 키가 필요 없습니다. 브라우저의 외부 API 접근(CORS)이 허용되어야 합니다. 리더보드가 차단되면 해당 JSON을 내려받아 주소 파일로 가져오세요. Info API가 차단되면 정적 HTML만으로 우회할 수 없으며 직접 운영하는 수집 서버가 필요합니다.

자동 누적: 전체 패키지의 collector.py와 .github/workflows/collect.yml을 함께 배포하면 GitHub Actions가 브라우저와 무관하게 실행됩니다. 기본값은 평가액 상위 5,000개를 최초 선정해 고정 추적하며, 2시간마다 수집합니다. 첫 수집은 수십 분이 걸릴 수 있습니다. 하루 12회 기준 85개 기록은 약 7일이 필요합니다. 스케줄 지연·실패 시 더 오래 걸립니다. 청산 데이터는 기본 180회 보관합니다. WALLET_LIMIT=0은 리더보드 전부를 의미하며 전체 시장 전수는 아닙니다. 전부 수집하려면 워크플로 주기를 6시간 이상으로 늘리세요.

전체 시장에 가까운 목록을 만들려면 HyperCore 노드/인덱서에서 계정 및 거래 참여 주소를 지속적으로 수집·중복 제거한 뒤 이 입력에 연결해야 합니다. Arbitrum 브리지 입출금 주소만으로 현재 포지션 보유자를 전부 찾을 수 없습니다.
